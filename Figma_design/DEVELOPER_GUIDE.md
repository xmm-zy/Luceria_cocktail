## 第二部分 · 前端开发

### 2.1 从 Figma 到代码
1. **打开 Dev Mode**（右上角 `</>`）。选中图层就能看到尺寸、间距和**变量名**。
2. **导出令牌**
   - 颜色：集合 `Luceria / Color`，3 种模式 `Dark`（默认）、`Light`、`High contrast`。
   - 间距与圆角：集合 `Luceria / Spacing & Radius`。
   - 字体：15 个文字样式，全部使用 Inter。
   - 阴影：Elevation/Card、Floating、Sheet，以及 Focus/Ring。
   - 代码里**只引用令牌名**，不要写死色值。模式要随系统外观和应用设置实时切换。
3. **先实现 02 Components 里的组件**，包括所有状态变体（开/关、选中、评分 1–5、按钮 3 种 × 3 种尺寸）。
4. **再拼屏幕**：使用自动布局的部分对应 flex/stack。绝对定位只用于 Hero 背景、浮动标签栏、提示条和弹层。
5. **交互以 10 Prototype 为准**：Present 模式下逐条走一遍，转场时长见 2.5 节。
6. **用 09 页验收三种主题**。

可选：figwright MCP 的 `get_design_context` 可以读取结构和数值，`get_screenshot` 只用来核对，不要拿截图量尺寸。

### 2.2 技术实现对照（不限框架）
| 设计概念 | SwiftUI | Web / Vue（原仓库） |
|---|---|---|
| 颜色变量 + 3 模式 | Asset Catalog（Any / Dark / High Contrast），结合 `colorScheme` 和 `colorSchemeContrast` | CSS 自定义属性 + `[data-theme]` + `prefers-contrast: more` |
| 文字样式 | `Font.custom("Inter", size:relativeTo:)`，支持 Dynamic Type | `rem` + `clamp()` |
| 浮动标签栏 | 自定义底部 overlay | `position: fixed` + `safe-area-inset-bottom` |
| 屏幕常亮 | `isIdleTimerDisabled` | Screen Wake Lock API |
| 朗读步骤 | `AVSpeechSynthesizer` | Web Speech API |
| 相机扫描 | `AVCaptureSession` + Vision | `getUserMedia` |

### 2.3 布局规则
- 屏幕左右边距 40 pt；状态栏占 24 pt，不放可点控件。
- 浮动标签栏 560 × 68 pt，水平居中，距底部 28 pt。可滚动内容留 120 pt 底部内边距。
- 触控目标至少 44 pt：普通按钮 52，大按钮 60，调酒页底部按钮 88。
- 配方网格 4 列、每列 266 pt、间距 16；分屏宽度小于 900 pt 时改为 3 列 / 单列。
- **首页 Hero**：文案块（`HeroCopy`）从 y 152 开始，按钮行底部 y ≈ 482，酒的插图底边与按钮行底边对齐。下方「Also ready tonight」从 y 546 开始，与 Hero 间距 64，和标签栏之间留出均衡的空白。

### 2.4 配色规则
**首页 Hero 背景取当前推荐酒的颜色（动态），但只是一层低饱和的底色。**
- 背景：线性渐变，`drink/<id>`（0%）→ `bg/base`（60%）。
- 插图后的光晕使用 `glow/<id>`，即该酒色相的提亮版本，约 30% 不透明度，做径向渐变。**光晕要明显可见，但不能用琥珀色**，避免蓝色酒配黄色光晕这种冲突。新增酒款时也要同时新增一个 `glow/<id>`。
- 约束：Dark 下明度 9–14%、饱和度 ≤ 25%；Light 下明度 88–94%、饱和度 ≤ 30%；High contrast 下一律 `#000000`。
- 按钮、胶囊、标签栏永远用 `accent` 和中性色，不随酒变色，所以在任何一款酒下操作都长一个样。
- 新增酒款：从插图主色取色，按上面的约束生成 Dark 和 Light 两个值，HC 设为黑色，然后在 Foundations 的对比度表里核对。
- 示例见 09 页的「Hero colour follows the drink」两行；原型里点「换一杯」可以看到切换效果。

**其他规则**
- 所有「渐变到透明」都用令牌 `bg/clear`，不要写 `#000000` 加透明度 0，否则浅色模式下会出现一圈灰边。
- 空状态、搜索、计时器不加晕光。
- 状态一律「图标 + 文字」，不单靠颜色区分。
- 计时器只用一种颜色：中性轨道加强调色进度，完成时整圈强调色加对勾，不切换成绿色。暂停时进度改为 `text/tertiary`。

### 2.5 高对比度模式
| 项目 | Dark / Light | High contrast |
|---|---|---|
| 背景、卡片 | 暖灰 | 纯黑，所有卡片、按钮、胶囊、弹层都加 1.5 pt 白色描边 |
| Hero、酒的底板 | 酒色渐变和光晕 | 纯黑 |
| 文字 | 主 / 次 / 三级灰 | 主、次级为白色，三级为 #E0E0E0 |
| 强调色 | 琥珀 / 墨绿 | 信号黄 #FFD60A，按钮上的文字为黑色 |
| 焦点环 | 柔和蓝 | 青色 #40C8FF，3 pt |

实现方式：中性背景的容器（`fill/1`、`fill/2`、`bg/elevated`、`fill/glass`）统一加 `outline/hc` 描边。这个令牌只在 HC 下可见，代码里不需要写条件判断。

### 2.6 交互与动效
| 触发 | 结果 | 动效（开启「减少动态效果」时一律改为 150 ms 淡入淡出） |
|---|---|---|
| 切换标签 | 每个标签保留自己的滚动位置 | 无动画 |
| 打开配方 / 开始调制 | 推入新页面 | 从右滑入，300 ms |
| 筛选、添加材料、收藏到合集 | 底部面板，下滑关闭 | 升起，250 ms |
| 调酒步骤 | 「Next」按钮、点屏幕任意处、或语音说「next」 | 300 ms |
| 计时 | 暂停 / 继续 / +10 s；结束时震动和提示音，2 秒后自动进入下一步 | 圆环动画 |
| 开关、勾选、评分 | 即时切换（原型中是可交互组件） | 200 ms |
| 保存、加入清单 | 提示条带「Undo」，4 秒后消失 | 200 ms |
| 游戏 | 在选择页选一个游戏，进入后全屏独占；关闭按钮回到选择页 | push |

调酒过程中保持屏幕常亮。离开调酒前必须弹出「Stop mixing?」确认，进度保留 10 分钟。

### 2.7 无障碍（前端负责）
- [ ] 三种模式下所有文字都通过 WCAG 2.2 AA（对比度表在 Foundations 页）
- [ ] 支持 Dynamic Type 到 200%，版面重排、文字不截断（`A01`）
- [ ] VoiceOver 朗读顺序与 `A02` 的编号一致；图标按钮都有标签（Figma 图层名「IconButton · …」）；装饰性插图对读屏隐藏
- [ ] 开启「Larger touch targets」时按钮从 52 增大到 64；支持 Switch Control 和全键盘访问
- [ ] 计时结束时同时有声音、震动和可选的屏幕闪烁；朗读时可显示字幕
- [ ] 「减少动态效果」「One instruction per screen」「Extra time on timers」三个开关都要生效

## 第三部分 · 后端开发

### 3.1 数据模型（建议）
| 实体 | 关键字段 |
|---|---|
| User | id、名称、头像、邮箱、登录方式、主题偏好、无障碍设置、单位、每周饮酒上限、年龄确认、零酒精模式、名称/头像最近修改时间（7 天才能改一次） |
| Ingredient | id、名称、类别（spirit / liqueur / fresh / mixer / bitters）、ABV、别名（用于搜索和识别）、可替代项 |
| BarItem | userId、ingredientId、存量（full / half / low / out）、「用完时自动加入清单」 |
| Recipe | id、名称、基酒、方法、杯型、冰型、装饰、ABV、时长、用量（ml，按每杯计）、步骤（标题、说明、可选计时秒数、用到的工具）、`hue` 颜色值（Dark / Light）、插图 URL、来源和授权信息 |
| Collection | userId、名称、recipeIds |
| JournalEntry | userId、recipeId、日期、份数、评分（1–5）、口味反馈（too bitter / just right / too sweet）、笔记、用时 |
| UserRecipe | 同 Recipe 字段，加上 private / shared 和保存次数 |
| ShoppingItem | userId、名称、分区（produce / bottles / mixers / other）、数量、勾选状态、来源（哪个配方或哪次库存不足） |
| Review / Story / Reply | 作者、内容、点赞、时间、审核状态 |
| Notification | 类型（low stock / tonight's pick / reply / weekly summary / shopping）、payload、已读 |

### 3.2 需要实现的服务和接口
- **推荐**：「今晚能调什么」= 配方材料全部在库；「只差一样」= 缺 1 种材料；「最值得买的下一瓶」= 能解锁最多新配方的那种材料；「今晚推荐」综合口味偏好、最近的日记和季节。
- **用量换算**：配方以 ml 存储，按份数缩放，按设置换算成 oz 或 cl（前端展示，后端提供原始数据）。
- **账号**：Apple / Google 登录，邮箱 6 位验证码（10 分钟有效，60 秒后才能重发），删除账号进入 30 天冷静期，支持数据导出。
- **同步**：离线优先，本地可用；恢复联网后合并冲突，失败时返回状态（对应 `Y01` 离线、`Y02` 同步失败）。
- **通知**：库存偏低、今晚推荐（每周五 18:00）、购物提醒（基于位置）、回复、每周总结；遵守勿扰时段。
- **社区**：故事、回复、评价；频率限制（注册 2 分钟后才能发帖，10 分钟内最多 6 条），审核、举报、屏蔽。
- **扫描识别**：酒标 OCR 或图像识别 → 匹配 Ingredient 的别名库；识别不确定时返回候选列表让用户选。
- **语音**：设备端识别优先（隐私），命令集 next / back / repeat / pause timer / add 10 seconds / how much <ingredient>。
- **派对**：按人数和每人杯数批量换算用量，对比库存，生成购物清单；准备时间线（`Prep timeline` 目前只有入口）。
- **理性饮酒**：统计每周杯数（来自日记）；达到上限后推荐里优先零酒精；零酒精模式只返回无酒精配方。

### 3.3 配方数据与授权
- 6 款经典配方的数据来自 **Difford's Guide**（diffordsguide.com），见 11 Handoff 页的数据表。**上线前必须确认授权**；拿不到授权就改用自有配方或其他已授权的数据源。
- Difford's 的照片不得使用。
- 每个 Recipe 都要记录来源和授权信息。

## 第四部分 · 素材与资源（开发人员负责补齐）

**原则**：设计稿里现有的插图大多来自原仓库，**质量和风格都不达标，只能作为位置和尺寸参考**。开发人员需要找到或委托制作合格的素材，并**自行补充更多符合要求的素材**，填满下面所有标记的位置，同时覆盖新增酒款。

### 4.1 合格素材的标准
- **酒的插图**：杯体完整（不能被裁切或平切），单杯居中，透明背景（PNG 或 SVG），约 600 × 750，统一的插画风格（参考 Negroni：墨线加单色系印刷感），用色低饱和、和琥珀强调色不冲突，不带文字、边框或背景色块。
- **同一套素材内风格一致**：线条粗细、上色方式、透视角度、光源方向都要统一。
- **颜色和谐**：插图主色决定该酒的 `drink/<id>` 令牌，取色后必须满足 2.4 节的明度和饱和度约束。
- **授权清楚**：自有、委托制作或有明确可商用授权，在资源清单里记录来源。

| # | 位置（Figma 标记） | 问题 | 需要的素材 |

## 附录 · 仓库中的设计文件
没有 Figma 权限，或者需要离线查阅时，可以使用仓库中的导出文件。它们都由同一个 Figma 文件导出，**内容以 Figma 为准**。
- `pages/`：Figma 每一页的完整画布，为矢量 PDF，包含屏幕下方的「ASSET TODO」批注。封面、设计规范、交付说明另有 PNG 预览。
- `screens/`：每个屏幕一张 PNG（1x，1194 × 834），文件名就是屏幕编号；`09_themes/` 是浅色和高对比度版本。
- `data/tokens.json`：颜色变量（Dark / Light / High contrast 三种模式）、文字样式、阴影、间距、圆角、屏幕尺寸。可直接转换成代码令牌。
- `data/prototype-links.json`：原型的 5 条流程和全部 409 个交互，格式为“屏幕 · 元素 → 动作 → 目标屏幕 · 转场”。
